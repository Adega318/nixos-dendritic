# Host Configurations

This directory contains per-machine (host) configurations. Each host declares a NixOS system (`configurations.nixos.<name>`) and a Home Manager configuration (`configurations.homeManager.<name>`); the generators in [`modules/flake/nixos.nix`](../flake/nixos.nix) and [`modules/flake/home.nix`](../flake/home.nix) materialize them into `nixosConfigurations` / `homeConfigurations`.

## Directory Structure

```
modules/hosts/
├── variables.nix          # Global values for options declared in modules/flake/variables.nix
├── sam/
│   ├── configuration.nix  # configurations.nixos.sam = { stateVersion, wallpaper, base16Scheme, module = { imports = with config.flake.modules.nixos; [ ... ]; config = { ... }; } }
│   ├── home.nix           # configurations.homeManager.sam = { module = { imports = with config.flake.modules.homeManager; [ ... ]; home.packages = [ ... ]; } }
│   └── hardware-configuration.nix  # Generated by nixos-generate-config (filesystems, kernel modules)
└── dean/
    ├── configuration.nix  # Same shape, module.imports = with config.flake.modules.nixos; [ ... ]
    ├── home.nix
    └── hardware-configuration.nix
```

`configuration.nix` and `home.nix` are thin wrappers — they only set `configurations.*.<name>` attributes; actual system logic lives in `modules/nixos/` and `modules/home/`.

## Variable Management

`modules/flake/variables.nix` declares the options; `variables.nix` in this directory provides the values (committed here for a single-user setup; for multi-user or secrets, move to `sops-nix`/`agenix`):

| Option | Notes |
| -------- | ------- |
| `user.username` | Used for `users.users.<name>` and `home.username`/`homeDirectory` |
| `user.email` | Consumed by `programs.git` |
| `user.hashedPassword` | Set for both hosts |
| `rootHashedPassword` | `users.users.root.hashedPassword` |

`stateVersion` is set per-host (`26.05`) — do not change after initial install without reading NixOS release notes.

## Adding a New Host

1. `mkdir modules/hosts/<name>`
2. Copy `sam/configuration.nix` + `sam/home.nix` as templates; adjust `wallpaper` (`../../../wallpapers/<file>.png`), `base16Scheme` (`catppuccin-mocha` | `gruvbox-dark-hard` | `tokyo-night-dark` | `null`), and the `imports` lists.
3. Generate hardware config on the target machine: `nixos-generate-config --show-hardware-config > modules/hosts/<name>/hardware-configuration.nix`. The file is auto-discovered by `import-tree` because it defines `configurations.nixos.<name>.module` (see `sam/hardware-configuration.nix:1`); no explicit import in `configuration.nix` is needed — verify with `nix flake show` and `nix flake check`.
4. No registration in `flake.nix` needed — `import-tree` discovers the new `configurations.*` declarations automatically.
5. Validate: `nix flake check` and `nixos-rebuild dry-build --flake .#<name>`.

## Theming Per Host

```nix
# modules/hosts/sam/configuration.nix
configurations.nixos.sam = {
  wallpaper = ../../../wallpapers/linux_atari.png;
  base16Scheme = "gruvbox-dark-hard"; # null → wallpaper colors only
  # ...
};
```

`stylix.image` and `stylix.base16Scheme` are injected for both NixOS and Home Manager (see `modules/flake/stylix.nix`). Available schemes are enumerated in `modules/flake/nixos.nix:26`.
